# CMS Книжного клуба

Админка «Книжного клуба». Формы вместо ручного JSON: добавляешь книгу, главу
с темами, встречу, карточки или спикера — CMS сама собирает файлы по схемам
[book-club-data](https://github.com/bookclubit/book-club-data), конвертирует
картинки в WebP и открывает pull request.

Всё добавленное видно списками (боковое меню: «Книги», «Главы и темы»,
«Карточки», «Встречи», «Посты», «Спикеры», «Заявки» — участие в клубе
и доклады) и редактируется: форма
предзаполняется текущими данными, правки уходят таким же pull request-ом.
Пути и id при редактировании не меняются (на них завязаны потребители);
исключение — встречи: при смене даты/названия файл переносится автоматически.

**Темы — часть главы, отдельного раздела для них нет.** Глава и её темы живут
в одном `chapter.json`, поэтому названия тем задаются сразу при создании главы
(по одному на строку), а спикеры и ссылки на видео, презентацию и доп.
материалы дозаполняются позже правкой той же главы — одним pull request-ом,
без конфликтов.

## Как это работает

- **Без бэкенда.** Статическое SPA (React + Vite + Tailwind v4). GitHub REST API
  отдаёт CORS-заголовки, поэтому браузер ходит в `api.github.com` напрямую.
- **Токен — только у админа.** На странице входа вводится fine-grained personal
  access token; он хранится в `localStorage` и никуда, кроме GitHub, не уходит.
- **Один PR — один коммит.** Файлы (включая бинарные WebP) собираются через Git
  Data API: blobs → tree → commit → branch → pull request.
- **JSON печатается как prettier** (`src/lib/json.ts`): 2 пробела, но короткие
  массивы — в одну строку. `JSON.stringify` так не умеет, и проверка
  `prettier --check` в pull request-е падала на каждом файле с коротким
  массивом (`topic_ids` встречи, `books` спикера).
- **Единый реестр `index.json` — генерируемый.** raw.githubusercontent.com не
  умеет листать директории, поэтому в корне book-club-data лежит реестр книг/
  глав/событий/спикеров. GitHub Action в book-club-data пересобирает его после
  каждого мержа, поэтому PR-ы CMS содержат только собственные файлы (спикеры —
  `speakers.json`, активная книга — `settings.json`), а miniapp и бот читают
  реестр вместо захардкоженных списков. В реестре есть **все** главы, включая
  пустые заготовки, — созданная глава сразу видна и в CMS, и в miniapp.

**Прошедшая встреча уходит в архив сама** — через 4 часа после начала
(`src/lib/events.ts`); тем же правилом живут вкладки «План»/«Архив»
в приложении клуба, темы в боте и архив заявок. Галочка «Встреча завершена»
в форме нужна, только чтобы убрать встречу раньше (отмена, перенос).

## Мерж из CMS

Открытые pull request-ы видны на «Обзоре» и (в части встреч) в блоке «Ждут
мержа» — у каждого кнопка **«Смержить»**, чтобы не ходить на GitHub за каждой
правкой. Мерж в два клика («Смержить» → «Точно смержить»): список общий, а
отменять мерж дороже, чем сделать лишний клик.

Перед мержем CMS спрашивает у GitHub состояние PR-а и честно отказывается,
если это черновик, есть конфликт с main или мерж заблокирован проверками.
После мержа ветка удаляется, а `index.json` пересобирает Action — в списках
правки появятся примерно через минуту.

## Встречи, которые ждут мержа

Созданная встреча живёт в открытом pull request-е и до мержа не видна ни в
списке встреч, ни в приложении. Чтобы её можно было доводить, на странице
«Встречи» сверху есть блок **«Ждут мержа»**: он находит открытые PR-ы, которые
меняют файлы `events/**`, и ведёт в форму с `?pr=<номер>`.

В этом режиме форма читает встречу **с ветки PR-а**, а публикация дописывает
коммит в ту же ветку — второй pull request не создаётся. Так можно догрузить
афишу, поправить ссылки на трансляции или перенести дату до мержа. Афиши при
этом уходят боту сразу (в репозиторий они не попадают вовсе), поэтому афишу дня
можно прикрепить к ещё не смерженной встрече.

## Посты о встречах в Telegram

При создании встречи CMS просит бота **подготовить** три поста: анонс, афишу
дня и напоминание. Сами они не публикуются: тексты ждут в разделе **«Посты»**,
где их видно целиком, можно поправить, пересобрать из данных клуба, заменить
картинку и отправить в выбранные группы (по умолчанию — во все).

Встреча передаётся полями формы — в book-club-data она появится только после
мержа pull request-а, а посты нужны раньше.

### Одобрение и публикация по расписанию

У каждого поста два пути: **«Опубликовать сейчас»** или **«Одобрить»** и
поставить время. Пока текст не одобрен, поле времени недоступно: по расписанию
уходят только те посты, которые админ прочитал и подтвердил.

- Время задаётся **в МСК** и подставляется подсказкой от бота: анонс — сейчас,
  афиша — 10:00 в день встречи, напоминание — за 10 минут до начала.
- Бот сверяется с расписанием раз в 5 минут, поэтому пост уйдёт в течение пяти
  минут после указанного времени.
- «Забрать на доработку» снимает одобрение вместе с расписанием. Пересборка
  текста из данных тоже сбрасывает одобрение — одобряли-то другой текст.
- Если автопубликация не удалась (бота выгнали из группы, отобрали права),
  в карточке видно причину и число попыток. После трёх неудач бот перестаёт
  пробовать и ждёт ручной публикации — вместо того чтобы стучаться каждые
  5 минут.

### Картинки постов

Картинка есть у каждого поста и меняется прямо в карточке: превью, «Выберите
файл» для замены, «Убрать картинку». Это работает и для **напоминания** —
раньше оно могло взять только афишу дня. Если своей картинки у напоминания нет,
бот по-прежнему подставит афишу дня.

- Группы подключаются **в самой группе** командой `/anons_here` от админа,
  отключаются `/anons_stop`. Групп может быть несколько; бот должен быть
  админом группы (для канала — обязательно).
- «Пересобрать из данных» обновляет текст свежими данными: подтверждённые
  позже спикеры и принятые презентации подтянутся.
- **Посты без эмодзи**: структуру держат жирные подзаголовки и подписи у ссылок.
  Ведущие и спикеры в тексте — ссылки на Telegram (ник из `speakers.json`,
  поэтому у ведущего должен быть заполнен Telegram), книга — ссылка на `url`
  из карточки книги, а если он пустой — на её страницу в приложении клуба.
- Правка текста в CMS переживает повторное сохранение встречи: бот не затирает
  то, что писали руками. Уже опубликованный пост не меняется — Telegram
  правит сообщения отдельно, этого CMS не делает.
- Афиши (`PosterPicker`) в репозиторий не попадают: файл уходит в бот и живёт
  в Telegram как `file_id`. Поэтому в WebP они не конвертируются — JPEG/PNG
  надёжнее для `sendPhoto`.
- Афишу можно загрузить и позже — правкой встречи (в том числе пока она ещё
  в открытом PR, см. «Ждут мержа») или прямо в карточке поста.
- Спикеров (`@username`) и презентации бот подставляет сам из заявок в D1 —
  в постах они появляются по мере подтверждения.
- Сбой подготовки постов не отменяет pull request: форма покажет
  предупреждение, а PR останется созданным.
- **Задание к встрече бот собирает сам** — из книги, главы с её названием и
  страниц: «прочитать главу 2 «Общие сведения о Docker», страницы 45–98 — на
  созвоне разбираем её вместе». Заполнять в форме нечего. Переопределить можно
  только вручную, полем `assignment` в файле встречи в book-club-data.

## Авторы книг

Отдельного раздела для авторов нет: автор существует ровно потому, что у него
есть книга, и живёт в `meta.json` своих книг. Чтобы у человека с несколькими
книгами они собрались в одну страницу автора (в приложении — `/author/<id>`),
у автора есть стабильный `id`.

Поэтому в формах книги (и «Новая книга», и правка) над списком авторов —
**выбор из тех, кто уже в клубе**: чип с аватаркой подставляет `id`, имя,
ссылку и готовую аватарку, загружать картинку заново не нужно. Список берётся
из `authors` в `index.json` (генератор собирает его из книг). Вручную заполняют
только нового автора — ему `id` выводится из имени транслитом.

Аватарку автора при правке книги CMS **перезаписывает по существующему пути** —
иначе у автора двух книг в одной осталась бы старая картинка.

## Заявки: участие в клубе и доклады

Страница «Заявки» — два блока.

- **Заявки на участие в клубе.** Приходят из приложения клуба или от бота
  (`/speaker`) вместе с рассказом о себе. **Пока заявка не одобрена, человек не
  может взять тему доклада** — ни в боте, ни в приложении. «Принять в клуб»
  открывает темы (бот сам напишет человеку), «Оформить спикером» ведёт в форму
  спикера с предзаполненными именем, Telegram и аватаркой из заявки.
- **Заявки на доклады.** Их подают уже участники клуба: бронь темы главы.
  Подтверждение занимает тему и запускает генерацию презентации.

**Telegram в профиле спикера обязателен** (и в «Новом спикере», и в правках):
по нику бот узнаёт участника и открывает ему темы без новых заявок. Форма
принимает `@username` или `t.me/username` и проверяет значение тем же правилом,
что и бот, — инвайт-ссылка (`t.me/+hash`) не пройдёт. Если у заявителя нет
`@username`, заявка помечается предупреждением: профиль спикера не оформить,
пока человек не заведёт ник.

## Дизайн-система

Токены — в `src/index.css` (`@theme` + переопределение под
`[data-theme="dark"]`), примитивы — в `src/components/ui.tsx`.

**Монохром.** Цвет в интерфейсе несёт только смысл — ошибка (`danger`) и,
изредка, предупреждение (`warn`). Кнопки, активные пункты меню и ссылки —
чернила, не синий: `accent` в токенах равен `ink`. Иерархию держат вес, размер
и волосяные линии, а не цветные плашки.

- Цвета только через токены: `canvas`/`surface`/`surface-2`, `ink`/`ink-soft`/
  `ink-faint`, `line`/`line-strong`, `accent`/`accent-hover`/`accent-soft`/
  `on-accent`, `success`/`warn`/`danger` (+ `-soft`). Нейтрали без хромы —
  это выбор, а не забывчивость. Никаких hex и `oklch()` вне блока токенов,
  никаких `bg-white`/`text-gray-*`
- Две темы: светлая и тёмная; выбор в `localStorage('cms-theme')`, инициализация
  скриптом в `index.html` (иначе тёмная мигает белым), переключатель —
  `components/ThemeToggle.tsx`. Новый цвет добавлять сразу в обе темы
- Один шрифт — Inter (400/500/600). `font-mono` — системный, только для slug-ов,
  id и путей; класс `.nums` — для колонок чисел. Базовый размер 14px, плотный
  текст интерфейса — 13px
- Навигация — боковое меню (`components/Layout.tsx`), списки — плотные таблицы
  на волосяных линиях, без рамки вокруг (`Table`/`Th`/`Td`/`Tr`/`TrGroup`:
  группа строк — подзаголовок внутри таблицы, а не вторая таблица). Формы —
  `Card` + `Field`, публикация — липкая `PublishPanel`. Строка списка ведёт
  на редактирование целиком, справа шеврон — цветных ссылок «Открыть» нет.
  Иконок-библиотек нет: интерфейс ведёт типографика
- У интерактивных элементов обязательны hover, `:focus-visible` (глобальный
  outline, без анимации появления), `:active` и `:disabled`; у кнопок — ещё и
  `loading`
- Радиусы `rounded-control`/`rounded-card`, переходы только на цвет/трансформ
  (`duration-120 ease-out`), `prefers-reduced-motion` уважается глобально

## Токен для входа

GitHub → Settings → Developer settings → Fine-grained tokens:

- Resource owner: `bookclubit`, repository: `book-club-data`
- Permissions: **Contents — Read and write**, **Pull requests — Read and write**

## Разработка

```bash
npm install
npm run dev      # локально
npm run build    # tsc + vite build
```

Переменные окружения — см. `.env.example` (`VITE_BOT_API` — URL API бота;
не задано — используется прод).

Деплой: Vercel, `npx vercel deploy --prod` (SPA-rewrite в `vercel.json`).
